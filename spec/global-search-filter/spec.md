# Feature Specification: 全局高级搜索过滤（Global Search Filter）

**Created**: 2026-11-05  
**Status**: Draft  
**Input**: User description: "我想要自定义一个高级搜索全局生效（或者复用设置）的功能。目前只有在添加画廊的时候，可以设置与非或，但是在搜索的时候，一些我不想看的内容还是会冒出来。查一下现在的功能是怎么实现的，这个配置能不能加到全局，或者说给搜索里面开放设置"

## Overview

NextE 的结构化"与/非/或"标签组合（EH 原生查询操作符：空格=与、`~`=或、`-`=非）目前只存在于首页自定义"画廊"标签页编辑器中，配置仅对该单个标签页生效。本功能新增一组**持久化的全局搜索过滤标签**：用户配置一次与/非/或标签组合（典型用途：排除不想看的内容）并启用后，应用在发送画廊搜索与画廊列表请求时自动把该组合合并进 EH 的搜索参数，用户无需在每次搜索中重复输入；配置不污染搜索输入框、不写入搜索历史；提供总开关，可临时停用而不清空配置。配置入口两处：搜索页过滤面板（直接编辑）与 设置→搜索（状态展示 + 管理入口）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在搜索过滤面板配置全局排除并立即生效 (Priority: P1)

用户打开搜索页执行搜索后，点漏斗图标打开过滤面板，在新增的"全局过滤"区：打开总开关，通过标签联想输入添加排除标签（如 `male:yaoi`、`language:english`），每个已添加标签行可切换 包含/任一/排除 三种关系、可滑动删除。面板内每次修改实时持久化；若当前已有搜索结果，则立即按合并后的查询重新执行。

**Why this priority**: 这是本功能的核心价值——"配置一次，每次搜索自动排除不想看的内容"。没有它整个功能不成立。

**Independent Test**: 打开搜索页 → 搜索任意词 → 打开过滤面板添加一个排除标签 → 验证结果立即刷新且被排除内容消失；再执行新搜索验证自动携带排除词。

**Acceptance Scenarios**:

1. **Given** 全局过滤未配置，**When** 用户在过滤面板启用总开关并添加排除标签 `male:yaoi`（当前已有搜索结果），**Then** 搜索立即以合并后的查询重新执行，结果列表中不再出现带该标签的画廊。
2. **Given** 全局过滤已启用（含 `-male:yaoi`），**When** 用户在搜索框输入 `female:stockings` 并搜索，**Then** 实际发送的请求查询为 `female:stockings -male:yaoi`，搜索输入框仍只显示 `female:stockings`，搜索历史记录的也是原始词 `female:stockings`。
3. **Given** 全局过滤已启用，**When** 用户在过滤面板关闭总开关，**Then** 配置保留、后续请求不再合并全局过滤词，当前已有搜索结果立即按无全局过滤重新执行。
4. **Given** 全局过滤已启用，**When** 用户在过滤面板滑动删除一个已配置标签，**Then** 删除立即持久化，当前搜索结果立即按剩余过滤词重新执行。

---

### User Story 2 - 首页画廊列表与无关键词浏览同样生效 (Priority: P2)

用户启用全局过滤后，首页的画廊类列表（内置"首页"标签的纯浏览、自定义"画廊"类型标签页）发出的列表请求同样自动合并全局过滤词；无搜索词的纯浏览请求直接以全局过滤词作为搜索参数发送。全局过滤变更时已加载的画廊类列表自动刷新；页面缓存按全局过滤状态隔离，不串用旧结果。

**Why this priority**: 用户明确要求"全局生效"覆盖首页画廊列表与无关键词浏览；它把过滤价值从"搜索场景"扩展到日常浏览场景。

**Independent Test**: 启用含一个排除标签的全局过滤 → 打开首页"首页"标签 → 验证列表无被排除内容；修改全局过滤 → 验证首页画廊列表自动刷新。

**Acceptance Scenarios**:

1. **Given** 全局过滤启用（含 `-male:yaoi`），**When** 用户打开首页内置"首页"标签（无关键词浏览），**Then** 列表请求携带全局过滤词作为搜索参数，列表中不出现带该标签的画廊。
2. **Given** 全局过滤启用，**When** 用户打开一个搜索词为 `language:chinese` 的自定义"画廊"标签页，**Then** 该列表请求的查询为 `language:chinese -male:yaoi`（合并、去重）。
3. **Given** 首页画廊类列表已加载，**When** 用户通过搜索过滤面板修改全局过滤（增删标签或切换开关），**Then** 已加载的画廊类列表自动重新加载，无需手动刷新或重启。
4. **Given** 全局过滤从启用改为停用，**When** 用户再次进入此前浏览过的画廊列表，**Then** 不会展示按旧过滤状态缓存的结果。

---

### User Story 3 - 设置→搜索 中查看状态并管理 (Priority: P3)

用户进入 设置→搜索，新增"全局搜索过滤"区：显示当前状态（未配置 / 已启用 N 个标签 / 已停用 N 个标签），并提供管理入口进入编辑页；编辑页提供与过滤面板一致的编辑能力（总开关、标签联想添加、包含/任一/排除切换、滑动删除），修改即时持久化并生效。

**Why this priority**: 提供独立于搜索场景的集中管理入口，用户不进入搜索也能查看和调整；优先级低于直接生效的 P1/P2。

**Independent Test**: 配置若干全局过滤标签 → 进入 设置→搜索 → 验证状态行正确 → 通过管理入口进入编辑页删除一个标签 → 验证状态更新且新搜索生效。

**Acceptance Scenarios**:

1. **Given** 全局过滤已配置 3 个标签且启用，**When** 用户查看 设置→搜索，**Then** 状态行显示"已启用 · 3 个标签"。
2. **Given** 全局过滤已配置但总开关关闭，**When** 用户查看 设置→搜索，**Then** 状态行显示"已停用 · N 个标签"。
3. **When** 用户从 设置→搜索 进入编辑页并删除一个标签，**Then** 删除立即持久化并全局生效，返回后状态行数字更新。

---

### Edge Cases

- **用户查询与全局过滤含完全相同的标签**（如用户主动输入 `-male:yaoi`，全局过滤也配了 `-male:yaoi`）：合并时按 token 完全去重，同一 token 只发送一次。
- **语义冲突不消解**：全局过滤排除 `language:chinese` 而用户主动搜索 `language:chinese` 时，两个 token 都发送，结果以 EH 服务器行为为准；产品不做智能对冲。
- **搜索范围切换**：过滤面板切到"收藏"范围时，全局过滤编辑区隐藏（收藏范围不适用）；切回"画廊"范围恢复显示。
- **不生效范围**：关注（watched）列表/搜索、收藏搜索、热门、排行的请求不合并全局过滤；这些入口行为与现状完全一致。
- **重启恢复**：应用重启后全局过滤（开关状态 + 标签列表）完整恢复；重启前已配置未保存的中间态不要求恢复。
- **过滤词为空**：总开关开启但无任何标签时视为未配置，不改变任何请求。
- **搜索历史**：只记录用户输入的原始词；从历史点击重新搜索时同样按原始词合并全局过滤。
- **页面缓存**：同一列表在不同全局过滤状态下的缓存条目相互隔离；修改过滤后新请求不命中旧缓存。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供持久化的全局搜索过滤配置，包含：启用开关、一组以与/非/或关系组织的标签（EH 原生操作符语义），应用重启后完整恢复。
- **FR-002**: 搜索页"画廊"范围的搜索请求 MUST 在发送时自动合并全局过滤词（token 完全去重）；合并结果 MUST NOT 回写搜索输入框、MUST NOT 写入搜索历史。
- **FR-003**: 首页画廊类列表请求（内置"首页"标签的无关键词浏览、自定义"画廊"类型标签页）MUST 同样合并全局过滤词；无用户搜索词时直接以全局过滤词作为搜索参数。
- **FR-004**: 关注（watched）列表/搜索、收藏搜索、热门、排行的请求 MUST NOT 合并全局过滤（行为与现状一致）。
- **FR-005**: 搜索页过滤面板 MUST 在"画廊"范围下提供"全局过滤"编辑区：总开关、带联想的标签添加、每个标签的 包含/任一/排除 关系切换、滑动删除；面板内修改 MUST 实时持久化并触发当前查询重新执行。
- **FR-006**: 设置→搜索 MUST 提供全局过滤的状态展示（未配置/已启用 N 个标签/已停用 N 个标签）与管理入口，管理入口的编辑能力 MUST 与过滤面板一致。
- **FR-007**: 全局过滤发生变更（增删标签、切换关系、切换总开关）时，当前已加载的搜索结果与首页画廊类列表 MUST 自动重新执行/刷新，无需重启或手动刷新。
- **FR-008**: 页面缓存 MUST 按全局过滤状态隔离，修改过滤状态后不得命中旧状态缓存。
- **FR-009**: 总开关关闭后，所有请求行为 MUST 与未配置全局过滤时完全一致，且配置内容保留。
- **FR-010**: 全局过滤配置 MUST 复用现有标签组合的交互与解析体系（标签联想、关系操作符、解析/序列化往返），保证与自定义标签页编辑器一致的体验与语义。

### Key Entities *(include if feature involves data)*

- **全局搜索过滤配置（Global Search Filter）**: 用户级配置实体。属性：启用开关（布尔）、标签组合（以与/非/或关系序列化的查询串）、内容版本（用于触发刷新与缓存隔离）。持久化于应用设置存储，随现有备份/恢复机制导出导入。
- **查询标签（QueryTag，复用现有）**: 单个查询 token——命名空间 + 文本 + 关系（与/或/非）。全局过滤的标签组合与自定义标签页搜索词共用同一解析/序列化规则。
- **合并后查询（Merged Query）**: 请求期派生值 = 用户原始查询 ∪ 全局过滤标签（token 完全去重），仅存在于请求构建环节，不落库、不回显。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 启用全局过滤后，100% 的画廊搜索与画廊列表请求携带合并后的过滤词；被排除标签的画廊不再出现在对应结果中。
- **SC-002**: 修改全局过滤后，无需重启应用或手动刷新，当前已加载的搜索结果/画廊列表即自动反映新过滤。
- **SC-003**: 应用重启后，全局过滤的开关状态与标签列表 100% 保留。
- **SC-004**: 关闭总开关后，所有画廊请求与"从未配置"时的行为完全一致（请求参数、缓存、列表内容）。
- **SC-005**: 搜索历史与搜索输入框 100% 只呈现用户原始输入，不出现全局过滤合并词。

## Assumptions

- EH 的 `f_search` 原生支持空格（与）/`~`（或）/`-`（非）操作符，全局过滤直接复用该语法，不依赖服务器新能力。
- 全局过滤标签数量不设硬性上限，由用户自律；异常超长由现有请求错误处理兜底。
- 全局过滤配置存于现有设置存储，自动纳入现有备份/恢复；不单独新增备份通道。
- 现有的分类、评分、页数等高级过滤与全局过滤相互独立、同时叠加生效，互不影响。
- 生效范围以用户选定为准：搜索页画廊搜索 + 首页画廊列表 + 无关键词纯浏览；watched/收藏/热门/排行不在本期范围。
- 不进入 EH 网站侧的 My Tags/隐藏标签体系，全局过滤是客户端请求期合并，与网站侧机制并存。
